# 4. SSE for progress, not WebSockets

**Decision:** The review page gets progress over Server-Sent Events, with polling as a fallback.

**Why:** Updates only flow server to browser, one way. SSE is plain HTTP, reconnects by itself, works with the existing cookie auth and needs no extra protocol or library. The stream sends the current state first, so a reload or a missed message never leaves the page stale.

**Cost:** Proxies must not buffer or cut long responses (a keep-alive comment is sent every 15 seconds). If the page ever needs to send messages to the server in real time, WebSockets would be the better fit.
