# 5. Own auth with database sessions

**Decision:** Email and password sign-in with argon2 hashes, and random session tokens stored hashed in Postgres, sent in HttpOnly, SameSite cookies. State-changing requests check the origin.

**Why:** It is a small, understandable surface that can be tested fully, and sessions can be revoked by deleting a row. Storing only the token hash means a database leak doesn't leak live sessions.

**Cost:** No password reset, email verification, social sign-in or two-factor yet. A managed auth service would give those, and would be the choice for a product with real users.
